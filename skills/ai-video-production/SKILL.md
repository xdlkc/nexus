# AI 视频制作流水线（总导演模式）

只解决一个问题：**用尽量少的钱、尽量低的抽卡率，做出一条自己满意的 AI 视频。**

核心分工是一条流水线，用户全程只和一个「导演」说话：

| 角色 | 负责 |
| --- | --- |
| 用户 | 选方向、确认画风、批准花钱；看动态、听声音 |
| 导演（Claude Code 等主 agent） | 写故事和分镜、写所有提示词、调用其他模型、抽帧放大检查、用代码做后期 |
| 画师（Codex） | 画设定图、样帧、每个镜头的首帧和尾帧 |
| 动画师（Seedance） | 把首尾帧变成几秒钟的视频 |
| 工具（ffmpeg / Python） | 拼接、转场、调色、放大、卡点 |

## 铁律：把错误挡在花钱之前

> 提示词改几个字不要钱，重画一张图基本不要钱，但**重新生成视频按秒付费**。

所以成本阶梯是：

```
文字里能发现的错  →  不留到图上
图上能发现的错    →  不留到视频上
视频里能修的错    →  不重拍（先剪掉 / 先写代码修）
必须重拍的镜头    →  先改提示词或首尾帧，再重拍，只拍这一镜
```

任何一步都不允许「先出片再看着办」。

## 规矩（每次开工都要遵守）

1. 用户确认故事前，不画任何图。
2. 用户确认画风前，不画正式镜头。
3. 提交视频生成前，**另开一个 agent 审核**提示词和图片的每个细节，它只挑错、不改文件；通过后报价，用户同意才提交。
4. 视频有问题先想能不能用代码修，修不了才重拍，且只拍这一镜。
5. 新版本存新文件，不覆盖、不删除旧文件（旧片段可能比新的好）。
6. 你看不到真正的动态，也听不到声音——没看过、没听过的东西必须明确告诉用户，不许替他判断。
7. 不充值、不买额度。接口返回欠费就停，把已有片段先粗剪给用户看。
8. 所有产物放进一个**新的项目文件夹**，按 `01-story/ 02-shotlist/ 03-style/ 04-frames/ 05-prompts/ 06-clips/ 07-final/` 归档。

## 开工前：两件事

1. 问用户四个值：**片长、画幅、总预算、要不要配乐和字幕**。
2. 自检环境：Codex、ffmpeg、Python、`ARK_API_KEY` 是否可用，缺什么直接说。

调用方式（不要自己画图，也不要把 key 打印出来）：

```bash
# 画师：一次只画一张图，提示词开头固定加这句
codex exec --skip-git-repo-check -s read-only -i 参考图.png - < 提示词.txt
# 提示词第一行：Use your image generation tool to create exactly ONE image. Do not run shell commands.
# 出图位置：~/.codex/generated_images/<日志里的 session id>/

# 动画师：火山方舟
# POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks
# key 在环境变量 ARK_API_KEY 里
# 模型：doubao-seedance-2-5-260628（720p 约 ¥1.5/秒）
#       doubao-seedance-2-0-mini-260615（720p 约 ¥0.5/秒，预算紧就用它）
```

## 八步流水线

每一步的完整可复制提示词在 `references/prompts.md`，模型踩坑对照表在 `references/pitfalls.md`。

### 1. 想法 → 定稿剧情

用户随便讲一个想法即可，导演负责把它变成逐镜头故事。好故事的六条标准：

1. **符合现实逻辑**：每个转折都追问——为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？
2. **一句话说清想表达什么**：说不出来就说明剧情平淡，回去改。
3. **开头就要抓人**：最抓眼球的画面放最前，写清第几秒出现什么。
4. **旁人反应要像真人**：每个包袱/转折分三段写「问题 → 主角怎么解决 → 旁人什么反应」，反应要有先后，绝不能几个人同一秒做同一个动作；细节要真实（人吃惊会往后缩）。
5. **AI 必须拍得出来**：避开模型固定弱点——人物交叉、手拿小东西、文字、镜子与倒影、左右不对称特征、一镜内换光、一人连做三个动作、俯拍看不到脸、配角太多。
6. **结构首选片段式**：镜头之间不用接戏，最稳；连贯式最容易穿帮，除非用户要求否则不用。

配歌时转折对副歌、关键动作对重拍。

剧情定稿后**另开一个 agent 只读故事、只挑错**（新 agent 像第一次看片的观众，能暴露主 agent 因长时间对话产生的自动脑补）。

### 2. 分镜：镜头语言、构图、配色

这一步决定成片质量，重要性甚至高于剧情。故事再好，镜头没设计好画面就平淡。

- 有参考片就让导演**逐帧量**机位、进出画比例再模仿；没有参考片按下列要求自己构思。
- 每个镜头必须写清：景别、机位、运镜、谁往哪走（写画面左右）、靠什么表情推进、这个镜头**是什么在动**、怎么转到下一镜。
- **每镜换角度**：全片平视正面最多两次，其余用俯拍、仰拍、背后、过肩、透过物体拍。
- **画面里一直有东西在动**：人或物走进/走出画面；人不动的镜头让纸飘过、路人走过；固定机位更要让人从远走到近。全片不要连着几个同景别，全身/半身/特写换着来。
- **运动要有理由**：跟着一个东西走、慢慢推近给特写、从近拉远。该动就动、该静就静，要靠对比，不能全程晃。
- **每一秒截图都要好看**：人的头或眼睛落在画面从左往右约 38% 或 62% 处，不放正中。
- **配色单独设计**：画第一张图之前定好，列成「每场用什么颜色」的色表；再用代码给每镜画 1920×1080 色块草图（标出 38%/62% 与主体），拼成总表给用户确认；最后转黑白检查——人和背景分不开就说明明暗对比不够，重配。

### 3. 定画风 + 画设定图

确定绘画风格（手绘柔和、剪纸线条、写实照片感、美式动画线条……），有参考图直接给。导演写提示词、Codex 画、用户看是否对味。

画风定下后，给**每个角色和固定道具**画设定图（正面、侧面、几个表情）。人物身上固定元素必须写死位置（例如「纹身在左小臂」），否则后面每张图都会漂移。

### 4. 出首尾帧（降低抽卡率最关键的一步）

纯文字生成视频容易出逻辑错误；雨、帽子、纹身这类小物件只写在文字里会拍着拍着就消失，**必须首帧和尾帧都画上**。

顺序固定：

1. 先让导演写出每镜「首帧画什么 / 尾帧画什么 / 中间发生什么」，审核 agent 通过后再画（省 Codex 额度）。
2. 先画内容最多的那张（一般是尾帧），再在尾帧上改出首帧——保证两张图机位和构图一致。
3. 同地点、同机位的镜头直接在前一张图上局部修改，不重画。
4. 要「慢慢推近」的镜头，尾帧可以把首帧裁一块再放大（两张构图完全一样等于镜头不动）。
5. Codex 出图不一定精确 16:9，交给 Seedance 前先裁好，且**首尾帧尺寸必须一致**。

画完按 8 条清单逐张放大检查（道具前置、旁人反应提前摆位、多人不同姿势、留运动空间、风向统一、缩到手机大小看、找多余物、首尾帧叠图看错位）——清单见 `references/prompts.md`。

修图注意：Codex 改一小块也会整图重处理，所以小块修改要把改好的块贴回原图；额度用完就等恢复，不要买额度，也不要一次并发太多张。

### 5. 写视频提示词 + 提交前审核

出问题先怀疑提示词，再怀疑模型。固定用**七段式**：`【画风】【镜头】【构图与配色】【人物】【逐秒】【声音】【约束】`，逐秒写清每一小段发生什么，开头 `0–0.2 秒画面完全静止与首帧一致`，结尾 `最后 0.3 秒所有人停住与尾帧一致`。

写的时候对着 `references/pitfalls.md` 逐条查（同时动作、凭空出现、走反方向、歧义词、道具数量变化、负面表述无效等）。

**提交前必须另开审核 agent**，材料只给：提示词、首帧、尾帧、设定图、分镜表、配色规则；输出只有「通过 / 不通过 + 逐条要改什么」。这一步是低抽卡率的关键。

### 6. 生成视频

省钱技巧：

- 720p 生成，后期再放大到 1080p。
- 不拍测试片，直接拍第一个正式镜头，能用就赚了。
- 新做法先用一两个最难的镜头试，可行再批量提交。
- 预算紧用 2.0 mini（价格约为 2.5 的三分之一），复杂镜头才上 2.5。
- 声音要听过再用；2.5 即使写了「没有音乐」仍可能混进音乐，那就不用它的音轨，音效后期另加。

出问题依次尝试：**剪掉 → 用代码修 → 重拍（先改提示词或首尾帧，只拍这一镜）**，旧片段一律保留，最后一起挑。

### 7. 后期（全部用代码，ffmpeg + Python）

- 转场：按设计用某个物体盖屏或带过；运动模糊切 8–16 份、半帧快门。
- 调色：按故事分段，只调彩度与亮度，不动色相，保护强调色与肤色，不加颗粒/柔光/暗角。
- 色彩管理：Seedance 的 mp4 按 BT.601 解码，中间文件用无损格式，交付标 BT.709。
- 放大：720p 用 lanczos 到 1080p 加轻微锐化，不做整段插帧。
- 卡点：拍点只从原曲上测，不要在剪过的文件上测。
- 做完抽查切点前后各 3 帧。

### 8. 全片复核 + 交付

再开一个审核 agent，**只给成片、不给任何结论**，像观众一样从头看：全部解码、每镜取多张全分辨率帧、切点前后各 3 帧；先写看懂的故事，再列看不懂的地方；逐镜检查重复动作、道具数量、穿帮、突跳、颜色跳变、脸变形、画面文字；明确写出「查不了的东西」（动态手感、声音）；区分「硬伤」与「小问题」。

最后写一份经验总结，把画风、提示词、犯过的错沉淀到项目文件夹里。

## 四线程工作模式（可选，成片成功率最高）

把导演这一个角色拆成四个 agent 协同（子 agent 由主 agent 自己开）：

| 角色 | 负责 |
| --- | --- |
| 主做 | 负责所有制作 |
| 审核 | 每一步都检查，提交生成视频前必须明确写「通过」 |
| 监督 | 把用户说过的所有话整理成要求清单，盯有没有人忘记 |
| 代理 | 按用户偏好替用户决定，在事先同意的预算内批准提交，超出就停下来等 |

配合顺序：主做每完成一步 → 先交审核 → 再交监督；有分歧交代理裁决；所有决定与花费记进审核记录，用户回来可推翻任何决定。用户偏好清单的来源通常是对话记录（Claude Code 在 `~/.claude/projects/` 下）。

## 快速自查（交付前）

- [ ] 故事能一句话说清，且每个转折都过了一遍现实追问
- [ ] 没有出现模型的固定弱点画面，或用首尾帧/提示词规避了
- [ ] 每镜都有明确的「什么在动」与「为什么动」
- [ ] 配色有独立色表，转黑白后人能区分出来
- [ ] 每镜首尾帧尺寸一致、构图一致、道具数量一致
- [ ] 每条视频提示词都过了审核 agent，且通过
- [ ] 花钱前用户已批准报价
- [ ] 成片过了只读复核，硬伤已修或已说明
